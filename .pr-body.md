## Summary

- adds an exact-SHA build evidence artifact at `/build-info.json`
- makes the existing Cloudflare workflow the single, serialized deployment mutator
- opts the landing repo into the owner-approved Otta `merge-and-deploy` contract

```acceptance
GIVEN a pull request merged into main on this repo
WHEN the deploy completes and Otta verifies it
THEN otta.build serves a build-info artifact whose SHA equals the merge commit, so a deploy that silently failed to publish is detected instead of assumed successful
```

- [x] A build-info artifact is emitted at build time containing the deploying commit's full SHA
- [x] The SHA comes from the workflow's exact commit input, not a checked-in constant
- [x] The artifact is deployed to the stable `/build-info.json` URL
- [x] `.otta.yml` declares owner-approved production `merge-and-deploy` and SHA verification
- [x] A regression test rejects missing or malformed commit values

## Delivery safety

- `deploy.yml` is workflow-dispatch-only, preventing a merge push and Otta dispatch from racing two production writes.
- checkout and build evidence both use the exact `commit_sha` supplied by Otta.
- the production concurrency group no longer cancels an in-flight deployment.
- duplicate dispatches no-op when that exact SHA is already live, even across controllers.
- the workflow itself retries `/build-info.json` until it proves the deployed SHA.
- Cloudflare's competing Git integration remains explicitly checked as disabled.
