## Summary

- Adds `scripts/write-build-info.mjs`, a standalone script (invoked directly from `deploy.yml`, not a `src/` file or a `package.json` script entry — PR #15 is concurrently touching most of `src/`, `package.json`, and `bun.lock`, so this keeps the two branches' change surfaces disjoint) that stamps `dist/build-info.json` with the deploying commit's full 40-char SHA. Served at the stable public URL `https://otta.build/build-info.json` after deploy.
- The SHA: prefers `process.env.GITHUB_SHA` (set automatically on every GitHub Actions job — push and pull_request), falling back to `git rev-parse HEAD` for local builds, and throwing explicitly if neither is available. No checked-in constant, no silent empty/wrong value.
- Adds one step to `deploy.yml` ("Write build-info artifact", right after "Build") that runs the script. The two pre-existing guarded steps (PostHog syntax check, CF git-integration check) are untouched — not reordered, not edited.
- Adds `.otta.yml` declaring `merge-and-deploy` / `allow_production: true` / `target: production` / `verify: sha-match` / `health_url: https://otta.build/build-info.json`, so `otta-deploy-verify.sh` has something to check the deploy against instead of the absent-deploy-block `human-approve` default that's been stalling every PR here since this repo forked off the monorepo.

```acceptance
GIVEN a pull request merged into main on this repo
WHEN the deploy completes and Otta verifies it
THEN otta.build serves a build-info artifact whose SHA equals the merge commit, so a deploy that silently failed to publish is detected instead of assumed successful
```
